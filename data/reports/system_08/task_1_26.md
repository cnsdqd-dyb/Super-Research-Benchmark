## Finite Difference Approach to the Heston Model  
The Heston model leads to a two-dimensional partial differential equation (PDE) in the underlying price ($S$) and variance ($v$) for option values ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=The%20Heston%20Partial%20Differential%20Equation,sigma%24%20is%20the)). Solving this PDE numerically via finite differences requires discretizing the $S$ and $v$ domains (and time) into a grid. A finer grid (higher density of points) typically improves the accuracy of the solution by reducing discretization error, but it also increases computational cost. Conversely, a coarser grid runs faster but can produce larger errors if it fails to capture important variations in the solution. Thus, there is an inherent *trade-off between convergence speed and estimation accuracy* when using finite difference methods for Heston’s model. The key challenge is to choose the grid resolution fine enough for acceptable accuracy while keeping the computational effort reasonable.  

## Balancing Convergence Speed and Accuracy  
It is indeed possible to strike a balance between speed and accuracy by using clever numerical techniques and grid designs. Modern finite difference schemes for the Heston model have been developed to achieve higher accuracy with fewer grid points (faster convergence). For example, *high-order compact schemes* on non-uniform grids can attain fourth-order spatial accuracy, significantly outperforming standard second-order methods in error reduction ([www.sciencedirect.com](https://www.sciencedirect.com/science/article/pii/S0377042714002155#:~:text=stochastic%20volatility%20models%20on%20non,In)). Such high-order methods generate a given accuracy with a coarser grid than would a low-order scheme, effectively speeding up computation. Another approach is to use **adaptive or non-uniform grids**, allocating more points where the solution varies rapidly (e.g. near the strike or for low variances) and fewer points where the solution is smooth ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=A%20better%20picture%20of%20the,S)) ([www.mdpi.com](https://www.mdpi.com/1999-4893/12/2/30#:~:text=linearly%20stable%20finite%20difference%20method%2C,call%20options%2C%20in%20similar%20ways)). Adaptive grid refinement can **reduce computational cost while maintaining accuracy** by concentrating effort only where needed ([www.mdpi.com](https://www.mdpi.com/1999-4893/12/2/30#:~:text=linearly%20stable%20finite%20difference%20method%2C,call%20options%2C%20in%20similar%20ways)). Additionally, **ADI (Alternating Direction Implicit) splitting schemes** and other implicit integrators allow larger time-steps without losing stability, accelerating convergence in time ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=As%20I%20mentioned%20above%2C%20I,Model%20parameter%20sets%20from)) ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=Finally%20a%C2%A0fine%20grid%20was%20chosen,in%20both%20cases%20with%20500x250x150)). In summary, by using efficient solvers (e.g. multigrid or sparse grid techniques) and intelligent grid spacing, one can obtain fast convergence *and* high accuracy for Heston model pricing. There are reports of advanced finite difference implementations achieving very low pricing errors (on the order of 10^−6 to 10^−4) with optimized grids, while still running in reasonable time ([www.sciencedirect.com](https://www.sciencedirect.com/science/article/pii/S0898122114000200#:~:text=match%20at%20L1172%20accuracy%20of,acceptable%20accuracy%20and%20within%20a)) ([www.sciencedirect.com](https://www.sciencedirect.com/science/article/pii/S0377042714002155#:~:text=pricing%20under%20stochastic%20volatility%20on,smooth%20payoffs%20which)). This demonstrates that speed-versus-accuracy can be balanced; we don’t necessarily have to sacrifice one for the other.  

## Impact of Grid Density on Long-Term Option Pricing  
That said, the **selection of grid density is critical** – especially for long-maturity options. A grid that is too coarse (too few points in $S$, $v$, or time) can introduce significant discretization errors, and these errors become more pronounced for long-term options. The reason is that a longer time horizon allows the underlying price and volatility to explore a wider range of values, so the numerical domain and resolution must be sufficient to capture extreme scenarios. If the grid is sparse or truncated, the solver may mis-price far-out-of-the-money or deep-in-the-money scenarios that materially affect a long-dated option’s value. For instance, using an inadequate $S$-range or too large step sizes can cause the PDE solution to miss the contribution of tail events, leading to underestimation of option prices over long maturities. Similarly, a coarse variance grid might not resolve the dynamics of volatility well, yielding inaccuracies in the option’s time value. In one comparison, a Heston finite-difference solver that employed a denser grid in the volatility dimension achieved a smoother, more accurate pricing surface – the finer $v$-spacing **“helped smooth out the error curve”** and lowered overall errors ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=First%20that%20the%20non,option%20pricing%2C%20apart%20from%20its)). This highlights that insufficient grid density in any dimension will inflate error. In practice, one should refine the grid until the option price stabilizes (converges) to a consistent value; if a long-term option’s price changes noticeably with further grid refinement, the previous grid was not dense enough. Empirically, long-maturity European option prices under Heston can be computed with high precision, but only when the grid and time-step are chosen fine enough to satisfy the model’s numerical stability and accuracy criteria ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=Case%203%20Present%2012,8)). If those criteria are relaxed (for speed), the resulting price bias may be small for short expiries yet **accumulate for longer expiries**, potentially by several basis points or more in error. In summary, **grid density must be chosen carefully** for long-term options – an overly coarse grid will indeed introduce material errors in pricing, whereas an appropriately refined or adaptive grid can produce accurate results with reasonable efficiency.  

## Conclusion  
**Numerical solutions to the Heston model can balance convergence speed and accuracy**, but achieving this balance requires sophisticated methods and judicious grid design. Techniques like high-order finite differences, adaptive/non-uniform grids, and implicit time-stepping allow one to obtain accurate prices without an explosion in computation time ([www.sciencedirect.com](https://www.sciencedirect.com/science/article/pii/S0377042714002155#:~:text=stochastic%20volatility%20models%20on%20non,In)) ([www.mdpi.com](https://www.mdpi.com/1999-4893/12/2/30#:~:text=linearly%20stable%20finite%20difference%20method%2C,call%20options%2C%20in%20similar%20ways)). However, one cannot neglect grid resolution: using too sparse a grid or too large time steps will degrade accuracy. This is especially true for long-term option pricing, where the payoff’s sensitivity to extreme movements demands sufficient grid coverage. In practice, quants often start with a coarse grid for speed then incrementally refine it to check stability of the price. If the price doesn’t change beyond a tolerance, the grid is deemed adequate; if it does, the grid must be densified. Ultimately, **there is a trade-off** – you can accelerate convergence up to a point with clever algorithms, but **adequate grid density is non-negotiable for reliable long-maturity option values**. In other words, you should use the **finest grid that is feasible** for your application or leverage advanced numerical schemes to handle coarse grids with lower error, otherwise you risk significant pricing errors over long horizons ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=First%20that%20the%20non,option%20pricing%2C%20apart%20from%20its)) ([www.acenumerics.com](https://www.acenumerics.com/miscellaneous/old-fashioned-heston-pricer-vs-the-state-of-the-art#:~:text=Case%203%20Present%2012,8)). The good news is that with modern methods, one can often achieve both speed and accuracy, provided that the grid is designed and tested carefully.
