**Threshold-based rules:** In practice, order‐tracking systems flag an anomaly whenever a monitored metric exceeds a predefined limit.  In other words, each key metric (delivery time, processing time, package weight, quantity, etc.) has a “critical threshold” set by the system.  If the metric goes beyond that threshold, an alert is raised.  For example, a logistics tracking patent specifies that when the calculated time-lateness value exceeds its set threshold, an “order time abnormal” warning is generated ([patents.google.com](https://patents.google.com/patent/CN110598940B/en#:~:text=s2%3A%20using%20the%20formula%20YC_%7BRj%7D%EF%BC%9D%28TD,value%2C%20generating%20an%20order%20time)).  Likewise, if a package’s weight or quantity deviates beyond its allowed threshold, a “weight abnormal” alert is triggered ([patents.google.com](https://patents.google.com/patent/CN110598940B/en#:~:text=order%20is%20received%20before%2C%20the,an%20order%20weight%20abnormal%20instruction)).  In general monitoring systems, this is just like any alert – “an alert is a notification that occurs when a metric…goes above a threshold target that you have set” ([www.sciencedirect.com](https://www.sciencedirect.com/topics/computer-science/critical-threshold#:~:text=An%20alert%20is%20a%20notification,every%20time%20you%20log%20into)). 

**Examples of order metrics and thresholds:** Typical anomalies include excessive delays or unexpected values.  *Delivery/processing time:*  If an order’s elapsed transit time exceeds its forecasted deadline by more than the configured allowance, the system flags it as late.  (E.g. patent CN110598940B sets a threshold on the “time abnormal value” – when the order time exceeds that threshold, a time-abnormal alert is issued ([patents.google.com](https://patents.google.com/patent/CN110598940B/en#:~:text=s2%3A%20using%20the%20formula%20YC_%7BRj%7D%EF%BC%9D%28TD,value%2C%20generating%20an%20order%20time)).)  *Weight/quantity:*  If the measured weight or quantity of an order differs from the expected amount by more than a tolerance, a weight- or count-anomaly is raised ([patents.google.com](https://patents.google.com/patent/CN110598940B/en#:~:text=order%20is%20received%20before%2C%20the,an%20order%20weight%20abnormal%20instruction)).  *Other metrics:*  Some systems also monitor scan/drop events or failure rates; any value breaching its limit (such as returns, defects or scan gaps beyond X%) triggers an anomaly warning.  In all cases, the “critical threshold” is simply the cutoff defined in the rules.  

**Statistical/ML thresholds:** More advanced detectors work similarly but use learned thresholds.  For instance, a 3-sigma rule would flag any order metric lying more than three standard deviations from its historical mean.  Or in a K-nearest neighbors model, each order is scored by its distance to normal patterns, and “if the distance is greater than the threshold value, it is considered an anomaly” ([www.mdpi.com](https://www.mdpi.com/2304-8158/11/14/2076#:~:text=This%20method%20considers%20anomalies%20far,42)).  In practice, such systems calibrate a cutoff (anomaly score or distance) so that any order exceeding it yields a warning.  

In summary, there isn’t one universal number; an “anomaly warning” is simply triggered by crossing the system’s preset limit.  In other words, whenever an order tracking metric (time, weight, count, anomaly score, etc.) breaches its defined critical threshold, the system generates an anomaly alert ([patents.google.com](https://patents.google.com/patent/CN110598940B/en#:~:text=s2%3A%20using%20the%20formula%20YC_%7BRj%7D%EF%BC%9D%28TD,value%2C%20generating%20an%20order%20time)) ([www.mdpi.com](https://www.mdpi.com/2304-8158/11/14/2076#:~:text=This%20method%20considers%20anomalies%20far,42)).
