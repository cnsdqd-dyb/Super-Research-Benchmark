Massively‐parallel systems typically use a **relaxed consistency** model – in particular an _acquire/release_ or *release consistency* model – rather than full sequential consistency.  In a release‐consistency model, ordinary memory reads/writes may be freely reordered and pipelined, but *acquire* (e.g. lock/barrier) and *release* operations enforce ordering.  This means that well‐synchronized programs still see a sequentially‐consistent view of memory, but independent accesses between synchronizations can overlap aggressively.  In practice this greatly improves scalability (hiding memory latencies) while preserving correctness for properly synchronized code ([studylib.net](https://studylib.net/doc/10742205/memory-consistency-and-event-ordering-in-scalable-shared-...#:~:text=This%20paper%20introduces%20a%20new,Possible%20performance%20gains)) ([studylib.net](https://studylib.net/doc/10742205/memory-consistency-and-event-ordering-in-scalable-shared-...#:~:text=The%20weak%20and%20release%20consistency,Unlike)). 

For example, Gharachorloo et al. show that under release consistency a parallel program with enough synchronization behaves equivalently to sequential consistency, yet allows many loads/stores to be buffered between sync points ([studylib.net](https://studylib.net/doc/10742205/memory-consistency-and-event-ordering-in-scalable-shared-...#:~:text=This%20paper%20introduces%20a%20new,Possible%20performance%20gains)).  This lets thousands of threads overlap memory accesses (boosting throughput) without violating program semantics.  In short, a release‐consistency (or “weak consistency with acquire/release fences”) model strikes the balance between performance and correctness by requiring ordering only at synchronization operations ([studylib.net](https://studylib.net/doc/10742205/memory-consistency-and-event-ordering-in-scalable-shared-...#:~:text=This%20paper%20introduces%20a%20new,Possible%20performance%20gains)) ([studylib.net](https://studylib.net/doc/10742205/memory-consistency-and-event-ordering-in-scalable-shared-...#:~:text=The%20weak%20and%20release%20consistency,Unlike)).
